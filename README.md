# currency-rates-app

Небольшой сервис курсов валют на Flask. Берёт курсы у публичного API (`api.frankfurter.app`, ключ не нужен) и отдаёт их в упрощённом виде.

### Структура
```
├── app.py            # Flask-приложение
├── rates.py          # вспомогательный модуль (сборка URL, форматирование)
└── requirements.txt  # flask, requests
```

### Как работает
- `GET /` — описание сервиса
- `GET /health` — проверка состояния
- `GET /rates/<BASE>` — курсы валюты `BASE` к EUR, GBP, PLN, CZK

```bash
curl http://127.0.0.1:<порт>/rates/USD
```

Настройки читаются из переменных окружения:

| Переменная | По умолчанию |
|---|---|
| `APP_HOST` | `127.0.0.1` |
| `APP_PORT` | `6100` |

Запуск без Docker: `pip install -r requirements.txt && python app.py`.

## Задача: упаковать приложение в Docker (без Docker Compose)

Напиши `Dockerfile` и разверни приложение в контейнере. Compose здесь не нужен, всё делается через `docker build` и `docker run`. Готового решения в репозитории нет.

### Основная часть
1. Напиши `Dockerfile`. Приложение состоит из двух `.py`-файлов и зависимостей, нужно скопировать всё необходимое.
2. Добавь `.dockerignore`: в образ не должны попасть `__pycache__/`, `.git/`, `venv/`, `.env`.
3. Собери образ с именем `currency-rates` и тегом `v1`.
4. Запусти контейнер в фоне с именем `rates-app`. На хосте сервис должен быть доступен на порту `8100`.
5. Проверь `docker ps`, затем `curl http://127.0.0.1:8100/health` и `curl http://127.0.0.1:8100/rates/USD`.
6. Посмотри логи контейнера (`docker logs`).

Если на шаге 5 `curl` с хоста не достучался, хотя контейнер в статусе `Up`, проблема не в Docker, а в том, **на каком адресе приложение слушает внутри контейнера**. Посмотри на конец `app.py` и подумай, как это поменять, не трогая код (подсказка: есть два способа задать переменную окружения, один при сборке образа, другой при запуске контейнера. Попробуй оба и пойми разницу).

Если `/rates/USD` отвечает `502`, это сеть на стороне машины (нет выхода наружу), а не ошибка Dockerfile: проверь `curl https://api.frankfurter.app/latest` с самого хоста.

### Практика слоёв и размера
7. **Кэш слоёв.** Измени любую строку в `rates.py` и пересобери образ как `v2`. Какие шаги сборки взяты из кэша (`CACHED`), а какие выполнились заново? Если `pip install` выполнился повторно, значит порядок инструкций в `Dockerfile` неудачный. Исправь.
8. **Размер.** Сравни размер образа на базе `python:3.12` и на базе `python:3.12-slim` (`docker images`). Что выбрал бы для продакшена и почему?
9. **Не от root.** Сделай так, чтобы процесс в контейнере работал от обычного пользователя, а не от root. Проверь командой `docker exec rates-app whoami`.

### Уборка
10. Останови и удали контейнер, затем удали образы `v1` и `v2`.
